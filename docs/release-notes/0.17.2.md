# Model Streamer 0.17.2 - Release Notes

Model Streamer 0.17.2 is a patch release for 0.17.1. Both changes were cherry-picked onto `release/0.17`. **A web identity credential exchange no longer fails TLS verification on aarch64**, which ended every `s3://` load that used web identity credentials in 0.17.0 and 0.17.1 with `File access error`. **Distributed streaming recognizes a process group with a device-prefixed backend**, such as `cuda:nccl,cpu:gloo`, which it had treated as a backend it does not support by default. The wheels are still tagged `manylinux_2_28`.

## Summary

### S3: aarch64 Web Identity Credentials & AWS SDK 1.11.924

On aarch64, the credential exchange for a web identity (`AWS_ROLE_ARN` with `AWS_WEB_IDENTITY_TOKEN_FILE`) sent its request to the AWS security token service through a libcurl that was built without a CA path. TLS verification failed with `curlCode: 60`, and every `s3://` load ended with `File access error`. Reads with static keys were not affected. The bundled AWS SDK for C++ moved from 1.11.584 to 1.11.924, which sends the web identity request through the AWS Common Runtime, and that finds the CA store at run time ([#344](https://github.com/dsx-ai-factory/model-streamer/pull/344), from [#343](https://github.com/dsx-ai-factory/model-streamer/pull/343)).

### Distributed Streaming: Device-Prefixed Backends

`dist.get_backend()` returns the string a process group was created with, so a group created with `cuda:nccl,cpu:gloo` never equaled `nccl` or `gloo`. In the default `auto` mode the streamer then logged that the backend was not supported by default and read without distribution, and it skipped the free-memory check. The streamer now reads the backend that serves the target device from `dist.get_backend_config()`, so such a group streams distributed to CUDA devices ([#331](https://github.com/dsx-ai-factory/model-streamer/pull/331), from [#322](https://github.com/dsx-ai-factory/model-streamer/pull/322)).

## Baseline

| Component | Requirement |
|---|---|
| Operating system | Linux with glibc 2.28 or newer (`manylinux_2_28` wheels) |

| Storage | Local and network file systems, S3 and S3-compatible stores, GCS and Azure Blob |

## Upgrade Notes

These matter when moving from 0.17.1. For 0.17.0, read the [0.17.1 notes](https://github.com/dsx-ai-factory/model-streamer/blob/master/docs/release-notes/0.17.1.md) first.

- **Device-prefixed process groups stream distributed.** In `auto` mode, a load to a CUDA device from a group created with a device-prefixed backend, such as `cuda:nccl,cpu:gloo`, now uses distributed streaming and runs the free-memory check on the device. In 0.17.1 it read without distribution. A load to a CPU device from the same group still reads without distribution unless `RUNAI_STREAMER_DIST=1`, because the group serves the CPU with `gloo` ([#331](https://github.com/dsx-ai-factory/model-streamer/pull/331), from [#322](https://github.com/dsx-ai-factory/model-streamer/pull/322)).
  > **Migrate:** To keep reading without distribution, set `RUNAI_STREAMER_DIST=0`. If you set `RUNAI_STREAMER_DIST=1` for such a group, CUDA devices no longer need it, and the free-memory check now applies to them. Read the free-memory check entry in [Known Issues](#known-issues) first.
- **The bundled AWS SDK for C++ is 1.11.924.** It was 1.11.584, for both architectures, and no setting changed ([#344](https://github.com/dsx-ai-factory/model-streamer/pull/344)). The PR ran credentials from an EC2 instance role (IMDSv2) and from EKS Pod Identity against local test servers on aarch64, and both worked before and after the upgrade.

## Bug Fixes

- **Web Identity Credentials on aarch64:** Fixed the credential exchange for a web identity failing TLS verification, which ended every `s3://` load with `File access error`. The PR checked the request against real AWS STS with a dummy token, which answered HTTP 400 `InvalidIdentityToken` as expected, and did not test a full exchange with a valid token. Container credentials fetched from a custom `https://` URL still use libcurl and still fail on aarch64. Reaches the Python and C APIs ([#344](https://github.com/dsx-ai-factory/model-streamer/pull/344), from [#343](https://github.com/dsx-ai-factory/model-streamer/pull/343), reported in [#337](https://github.com/dsx-ai-factory/model-streamer/issues/337)).
- **Device-Prefixed Backends:** Fixed `RUNAI_STREAMER_DIST=auto` not recognizing the NCCL backend of a group created with a device-prefixed backend. The free-memory check runs only for an NCCL backend of the target device, and NCCL is still refused for a CPU device. PyTorch 2.0 or newer is required, which the package already required. Reaches the Python API ([#331](https://github.com/dsx-ai-factory/model-streamer/pull/331), from [#322](https://github.com/dsx-ai-factory/model-streamer/pull/322), reported in [#321](https://github.com/dsx-ai-factory/model-streamer/issues/321)).

## Known Issues

### Distributed Streaming

#### Hang When Ranks Belong to Separate Model-Parallel Groups

Distributed streaming takes its participants from the default process group. In a deployment with separate model-parallel groups, such as SGLang with PP=2, TP=8 and an MTP draft model, ranks outside a worker's TP group enter different collectives, and the load hangs until the distributed timeout or the worker restarts ([#165](https://github.com/dsx-ai-factory/model-streamer/issues/165)). **Workaround:** Call `stream_file` or `stream_files` with `is_distributed=False`, the default. The load then skips rank discovery and runs without a collective, and gives up distributed read sharing. `RUNAI_STREAMER_DIST=0` is not enough: a call with `is_distributed=True` still discovers the ranks before the variable is checked.

#### Free-Memory Check Admits Loads That Fail or Hang

Before distributed streaming starts on an NCCL backend, each rank compares the free memory of a CUDA device with twice the largest chunk. Three defects were present before 0.17.2, and device-prefixed groups now reach them. The check measures the current device of the process, not the target device ([#330](https://github.com/dsx-ai-factory/model-streamer/issues/330)). Its threshold is smaller than the two staging buffers allocated afterward, `max(1 GiB, largest chunk)` each, so a device can pass the check and then run out of memory ([#328](https://github.com/dsx-ai-factory/model-streamer/issues/328)). Each rank also decides on its own, so when free memory differs between ranks, some fall back to non-distributed streaming while the others wait in a collective until the distributed timeout, 600 seconds by default ([#329](https://github.com/dsx-ai-factory/model-streamer/issues/329)). **Workaround:** Set `RUNAI_STREAMER_DIST=0`. The check is skipped and every rank reads without distribution, which gives up distributed read sharing. A call with `is_distributed=True` still discovers the ranks first, so every rank must make the call.
