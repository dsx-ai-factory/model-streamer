# Model Streamer 0.17.3 - Release Notes

Model Streamer 0.17.3 is a patch release for 0.17.2. Its one change was cherry-picked onto `release/0.17`. **The experimental Azure Blob cache provider is discovered under its new package name, `py_dacs_client`**, and the `py_tachyon_client` package is no longer searched. The wheels are still tagged `manylinux_2_28`.

## Summary

### Azure Blob Cache Provider: `dacs-client` Discovery

The Python package that ships the cache library `libStorageDirect.so` was renamed, and its import package changed from `py_tachyon_client` to `py_dacs_client`. The streamer looks for the library in the `py_dacs_client` package, so a cache provider installed with `pip install dacs-client` is found again. Before it searches the package, the streamer checks `RUNAI_STREAMER_EXPERIMENTAL_AZURE_CACHE_LIB`, which defaults to `/opt/cache-client/usr/local/lib/python3.10/dist-packages/py_dacs_client/libStorageDirect.so`. A path that is missing or is not a regular file is ignored, with a warning when you set it, and the search continues in the package. The library file name did not change ([#351](https://github.com/dsx-ai-factory/model-streamer/pull/351), from [#159](https://github.com/dsx-ai-factory/model-streamer/pull/159)).

## Baseline

| Component | Requirement |
|---|---|
| Operating system | Linux with glibc 2.28 or newer (`manylinux_2_28` wheels) |
| Architectures | x86_64 and aarch64 |
| Framework | PyTorch |
| Storage | Local and network file systems, S3 and S3-compatible stores, GCS and Azure Blob |
| Storage packages | `runai-model-streamer[s3]`, `[gcs]` or `[azure]`, installed at the same version as `runai-model-streamer` |
| GPU destinations (C API) | NVIDIA CUDA; `libcuda.so.1` is loaded at run time |

## Upgrade Notes

These matter when moving from 0.17.2. For 0.17.1 or earlier, read the [0.17.2 notes](https://github.com/dsx-ai-factory/model-streamer/blob/master/docs/release-notes/0.17.2.md) first.

- **The Azure Blob cache provider is no longer discovered from `py_tachyon_client`.** Only experimental Azure Blob reads through a cache provider are affected. With `RUNAI_STREAMER_EXPERIMENTAL_AZURE_CACHE_ENABLED` unset or `auto`, a deployment that still has `tachyon-client` installed reads Azure Blob through the Azure SDK, with no error. With `RUNAI_STREAMER_EXPERIMENTAL_AZURE_CACHE_ENABLED=1`, the load fails with `InvalidParameterError`, because no usable cache library is found ([#351](https://github.com/dsx-ai-factory/model-streamer/pull/351), from [#159](https://github.com/dsx-ai-factory/model-streamer/pull/159)).
  > **Migrate:** Install `dacs-client` in place of `tachyon-client`, or point `RUNAI_STREAMER_EXPERIMENTAL_AZURE_CACHE_LIB` at the full path of the library.

## Bug Fixes

- **Azure Blob Cache Provider Discovery:** Fixed the automatic discovery of the cache provider library after its Python package was renamed to `py_dacs_client`. The library is now also looked up at the default ImageVolume path, and `RUNAI_STREAMER_EXPERIMENTAL_AZURE_CACHE_LIB` now falls back to package discovery when its path is missing or not a regular file. The error for `RUNAI_STREAMER_EXPERIMENTAL_AZURE_CACHE_ENABLED=1` with no usable library now says so. Reaches the Python and C APIs through the Azure package ([#351](https://github.com/dsx-ai-factory/model-streamer/pull/351), from [#159](https://github.com/dsx-ai-factory/model-streamer/pull/159)).

## Testing & CI

- `azcache_provider_test` gained 162 lines of tests for the library path selection. The PR ran it with the x86_64 config: 28 passed and 2 skipped. The two skips need the library at the default ImageVolume path. The PR did not run the full C++ suite or a Blob streaming test ([#351](https://github.com/dsx-ai-factory/model-streamer/pull/351)).
