# Model Streamer 0.17.0 - Release Notes

Model Streamer 0.17.0 **bounds host memory** during loads: reads go through a ring of reusable buffers, and the 40 GB memory limit now also covers distributed streaming. File reads are **faster by default**, through asynchronous direct I/O and a span-based split of the work between ranks. The C API is now a **C/C++ SDK** that can stream into NVIDIA GPU memory without Python. Every tensor the streamer yields is **owned by the caller**, `tensor_names` **loads a subset of a checkpoint**, and S3 reads can **retry a failed chunk**. Measured for the ring buffer change ([#167](https://github.com/dsx-ai-factory/model-streamer/pull/167)), a DeepSeek-V4-Pro (831 GiB, FP8) load at TP=8 on 8 H200 GPUs took 114 seconds with no page reclaim, against 120 seconds and 395 GB of page reclaim on 0.16.1.

## Summary

### Host Memory: Bounded Ring Buffer & Concurrent Requests

The streamer no longer reads into one buffer sized for the whole model. It reads into a ring of reusable buffers, refills each one as soon as the caller has consumed it, and keeps several submissions in flight at once ([#160](https://github.com/dsx-ai-factory/model-streamer/pull/160), [#167](https://github.com/dsx-ai-factory/model-streamer/pull/167)). `RUNAI_STREAMER_MEMORY_LIMIT` now applies to distributed streaming as a total for the node, 40 GB by default, divided between the ranks on that node. `RUNAI_STREAMER_RING_BUFFERS` sets how many buffers it is divided into, 18 by default. On DeepSeek-V4-Pro (831 GiB, FP8, TP=8, 8 H200 GPUs, virtiofs, cold cache, mean of 3 runs) the PR measured 114.4 seconds with no page reclaim and 1479 GB of host memory free at the low point. 0.16.1 with an unlimited limit took 120.5 seconds, reclaimed 395 GB of pages and fell to 681 GB free.

### File Reads: Direct Asynchronous I/O & Span Partitioning

File system reads now use `io_uring` with `O_DIRECT` when the host allows it, fall back to `libaio` with `O_DIRECT`, and then to the thread pool of buffered reads ([#178](https://github.com/dsx-ai-factory/model-streamer/pull/178)). Availability is probed, not read from the kernel version, because a container's default seccomp profile can block `io_uring_setup` on a kernel that reports it as available. Distributed streaming now splits the file list between ranks by spans of adjacent tensors, which keeps each rank's reads close together on disk. The PR measured a 15% faster DeepSeek-V4 load at TP=8 from virtiofs and no change from NFS. `RUNAI_STREAMER_CONCURRENCY` is split into `RUNAI_STREAMER_FS_QUEUE_DEPTH`, which takes a depth per file system type, and `RUNAI_STREAMER_OBJ_CONCURRENCY`; the old variable still supplies both when they are unset ([#188](https://github.com/dsx-ai-factory/model-streamer/pull/188)).

### C/C++ SDK: GPU Destinations & Scatter-Gather Reads

A C or C++ program can now include the headers, link `libstreamer.so` and stream without Python ([#193](https://github.com/dsx-ai-factory/model-streamer/pull/193)). Each read range carries its own source offset, size and destination pointer, and ranges need not be contiguous or in order ([#163](https://github.com/dsx-ai-factory/model-streamer/pull/163)). A submission names the device its destinations live on ([#189](https://github.com/dsx-ai-factory/model-streamer/pull/189)). For an NVIDIA CUDA device the streamer reads into pinned host buffers and copies to the caller's device memory, so reads and copies overlap ([#224](https://github.com/dsx-ai-factory/model-streamer/pull/224)). Each release attaches one SDK archive per architecture ([#245](https://github.com/dsx-ai-factory/model-streamer/pull/245)). GPU destinations are reachable only through the C API: the Python API still reads to host memory.

### Tensors: Ownership & Selective Loading

Every tensor `SafetensorsStreamer` yields now belongs to the caller. It stays valid after the iteration advances and after the streamer closes, so a loader no longer has to clone it, and it is aligned for its dtype. `owned=False` brings back borrowed views ([#238](https://github.com/dsx-ai-factory/model-streamer/pull/238)). Passing `tensor_names` to `stream_file()` or `stream_files()` loads only those tensors from a checkpoint ([#196](https://github.com/dsx-ai-factory/model-streamer/pull/196)).

### Reliability & Security: S3 Retries & Safe Downloads

Setting `RUNAI_STREAMER_S3_TIMEOUT` retries only the chunk that failed, with jittered exponential backoff, instead of failing the whole load ([#170](https://github.com/dsx-ai-factory/model-streamer/pull/170)). Retries stay off until it is set. `pull_files()` now rejects object names that would write outside the destination directory, for S3, GCS and Azure ([#183](https://github.com/dsx-ai-factory/model-streamer/pull/183)).

### Packaging & Releases: Platform Wheels, SDK Archives & Gated Publishing

The four packages build as platform-specific wheels for x86_64 and aarch64 ([#169](https://github.com/dsx-ai-factory/model-streamer/pull/169), [#228](https://github.com/dsx-ai-factory/model-streamer/pull/228)). A pushed `X.Y.Z` tag builds every package for both architectures, runs the integration and file system strategy tests, and publishes only after approval in the `pypi` environment. The GitHub release gets the wheels, both SDK archives and one `SHA256SUMS` ([#242](https://github.com/dsx-ai-factory/model-streamer/pull/242), [#245](https://github.com/dsx-ai-factory/model-streamer/pull/245)).

## Baseline

| Component | Requirement |
|---|---|
| Operating system | Linux with glibc 2.30 or newer (`manylinux_2_30` wheels) |
| Architectures | x86_64 and aarch64 |
| Framework | PyTorch |
| Storage | Local and network file systems, S3 and S3-compatible stores, GCS and Azure Blob |
| Storage packages | `runai-model-streamer[s3]`, `[gcs]` or `[azure]`, installed at the same version as `runai-model-streamer` |

## Upgrade Notes

These matter when moving from 0.16.1.

- **Wheels need glibc 2.30 or newer.** The 0.17.0 wheels are tagged `manylinux_2_30`; the 0.16.1 wheels were tagged `manylinux2014` ([#169](https://github.com/dsx-ai-factory/model-streamer/pull/169), [#228](https://github.com/dsx-ai-factory/model-streamer/pull/228)).
  > **Migrate:** On a system with glibc 2.28 or 2.29, install 0.17.1, whose wheels are tagged `manylinux_2_28`.
- **Distributed streaming is memory limited.** `RUNAI_STREAMER_MEMORY_LIMIT` was ignored there and reads were unlimited. It is now a node total, 40 GB by default, divided between the ranks on the node ([#167](https://github.com/dsx-ai-factory/model-streamer/pull/167)).
  > **Migrate:** Multiply a value you set by the number of ranks on the node to keep the same amount per rank, or set `-1` for no limit.
- **Yielded tensors belong to the caller.** A loader that cloned every tensor to keep it can drop the clone ([#238](https://github.com/dsx-ai-factory/model-streamer/pull/238)).
  > **Migrate:** Pass `owned=False` to keep the previous behavior, where a tensor must be consumed before the iteration advances.
- **File reads use direct I/O by default.** `RUNAI_STREAMER_FS_STRATEGY` defaults to `io_uring_direct,libaio_direct,sync_buffered` and the first entry the host can serve wins. Direct reads bypass the page cache ([#178](https://github.com/dsx-ai-factory/model-streamer/pull/178)).
  > **Migrate:** Set `RUNAI_STREAMER_FS_STRATEGY=sync_buffered` to keep the previous reader.
- **Distributed streaming splits work by spans.** `RUNAI_STREAMER_PARTITION_POLICY` now defaults to `spans`; it was `chunks`. Every rank must use the same policy ([#178](https://github.com/dsx-ai-factory/model-streamer/pull/178)).
  > **Migrate:** Set `RUNAI_STREAMER_PARTITION_POLICY=chunks` on every rank to keep the previous split.
- **C API callers: `runai_request` has a new signature.** It takes per-range offsets, sizes and destinations and a device, and `runai_request` and `runai_response` now work with many submissions in flight ([#160](https://github.com/dsx-ai-factory/model-streamer/pull/160), [#163](https://github.com/dsx-ai-factory/model-streamer/pull/163), [#189](https://github.com/dsx-ai-factory/model-streamer/pull/189)).
  > **Migrate:** Pass the per-range arrays and a CPU device. The Python API is unchanged.
- **Install the storage packages at the same version.** The `s3`, `gcs` and `azure` packages ship a shared library that `runai-model-streamer` loads, and mixed versions are not supported. See [Matching versions](https://github.com/dsx-ai-factory/model-streamer/blob/0.17.0/docs/src/installation.md#matching-versions).

## Features & Improvements

### Host Memory

- **Ring Buffer:** Replaced the single reusable read buffer with a ring that refills each buffer as soon as the caller finishes it. A buffer is never smaller than the largest tensor, so a model with large tensors gets fewer buffers than `RUNAI_STREAMER_RING_BUFFERS` asks for ([#167](https://github.com/dsx-ai-factory/model-streamer/pull/167)).
- **Node-Wide Memory Limit:** Applied `RUNAI_STREAMER_MEMORY_LIMIT` to distributed streaming as a node total ([#167](https://github.com/dsx-ai-factory/model-streamer/pull/167)).
- **Concurrent Submissions:** Added a request API that accepts many submissions at once. Each object storage worker interleaves them, so a small late submission is served alongside a large one ([#160](https://github.com/dsx-ai-factory/model-streamer/pull/160)).

### File Reads

- **Direct Asynchronous Readers:** Added `io_uring` and `libaio` readers with `O_DIRECT`. `RUNAI_STREAMER_FS_STRATEGY` is an ordered list of `io_uring_direct`, `io_uring_buffered`, `libaio_direct` and `sync_buffered`, and an exhausted list is an error that names each candidate's reason ([#178](https://github.com/dsx-ai-factory/model-streamer/pull/178)).
- **Read Size:** Added `RUNAI_STREAMER_FS_CHUNK_BYTESIZE`, 8 MiB by default, for the asynchronous readers ([#178](https://github.com/dsx-ai-factory/model-streamer/pull/178)).
- **Per-Mount Queue Depth:** `RUNAI_STREAMER_FS_QUEUE_DEPTH` takes a depth per file system type, such as `64,nfs=32`, and `RUNAI_STREAMER_OBJ_CONCURRENCY` sets object storage concurrency ([#188](https://github.com/dsx-ai-factory/model-streamer/pull/188)).
- **Span Partitioning:** Added the `spans` policy for splitting tensors between ranks and made it the default ([#178](https://github.com/dsx-ai-factory/model-streamer/pull/178)).
- **Registered Buffers:** Turned on `io_uring` buffer registration, denied on `nfs`; `RUNAI_STREAMER_FS_REGISTER_BUFFERS` and `RUNAI_STREAMER_FS_NO_REGISTER_BUFFERS` control it ([#224](https://github.com/dsx-ai-factory/model-streamer/pull/224)).

### C/C++ SDK

- **Public C API:** Made the header valid C, rooted the include paths so they install, and published the response codes, so an external program can link against `libstreamer.so` ([#193](https://github.com/dsx-ai-factory/model-streamer/pull/193)).
- **Scatter-Gather Reads:** `runai_request` takes a source offset, size and destination per range ([#163](https://github.com/dsx-ai-factory/model-streamer/pull/163)).
- **Device Destinations:** Added CUDA destinations with one device per submission, a pool of pinned staging buffers and five response codes for device failures. `libcuda.so.1` is loaded with `dlopen`, so the library builds without a CUDA version and runs where no driver is installed ([#189](https://github.com/dsx-ai-factory/model-streamer/pull/189), [#224](https://github.com/dsx-ai-factory/model-streamer/pull/224)).
- **SDK Archives:** Releases attach `runai-model-streamer-cpp-sdk-<version>-linux-<arch>.tar.gz` with the public headers, the core, S3, GCS and Azure libraries, the license and the third-party notices ([#245](https://github.com/dsx-ai-factory/model-streamer/pull/245)).

### Tensors

- **Owned Tensors:** A tensor is the read buffer itself on the host, a fresh allocation on a device, and a per-tensor copy out of the staging buffer in distributed streaming ([#238](https://github.com/dsx-ai-factory/model-streamer/pull/238)).
- **Dtype Alignment:** Every yielded tensor is aligned for its dtype whatever `owned` is set to, so `owned=False` does not always mean copy-free ([#238](https://github.com/dsx-ai-factory/model-streamer/pull/238)).
- **Tensor Filter:** `tensor_names` accepts any collection and raises on an empty one or a name found in more than one file. The header is validated for the whole file, and a local file's length is checked for truncation and trailing bytes. With distributed streaming every rank must pass the same names, or the load hangs until `RUNAI_STREAMER_DIST_TIMEOUT`, 600 seconds by default ([#196](https://github.com/dsx-ai-factory/model-streamer/pull/196)).

### Reliability & Security

- **S3 Chunk Retries:** Retried transport failures and HTTP 5xx, 408 and 429 responses for a failed chunk only, with each chunk's window starting at its first submission. Permanent errors such as 400, 401, 403 and 404 fail at once. `RUNAI_STREAMER_S3_MAX_RETRIES` overrides the retry limit of the AWS CRT for each ranged read ([#170](https://github.com/dsx-ai-factory/model-streamer/pull/170)).
- **Safe Downloads:** Checked that every `pull_files()` destination stays inside the target directory before creating a directory or opening a file ([#183](https://github.com/dsx-ai-factory/model-streamer/pull/183)).

### Packaging & Releases

- **Platform Wheels:** Built the four packages as platform-specific wheels without a Python ABI tag, so the bundled shared libraries install in the right place ([#169](https://github.com/dsx-ai-factory/model-streamer/pull/169), [#228](https://github.com/dsx-ai-factory/model-streamer/pull/228)).
- **Gated Publication:** A tag must point at a commit on the matching `release/X.Y` branch. CI saves the eight wheels with `SHA256SUMS`, waits for approval, and publishes those exact files without rebuilding them ([#242](https://github.com/dsx-ai-factory/model-streamer/pull/242)).
- **Release-Branch CI:** Each `release/X.Y` branch builds and uses its own devcontainer image ([#241](https://github.com/dsx-ai-factory/model-streamer/pull/241)).
- **Licensing:** Added the NVIDIA copyright notice to the license, NVIDIA SPDX headers to the source files, and a CI check and pre-commit hook for the header ([#218](https://github.com/dsx-ai-factory/model-streamer/pull/218), [#236](https://github.com/dsx-ai-factory/model-streamer/pull/236), [#237](https://github.com/dsx-ai-factory/model-streamer/pull/237)).

## Known Issues

### Distributed Streaming

#### Hang When Ranks Belong to Separate Model-Parallel Groups

Distributed streaming takes its participants from the default process group. In a deployment with separate model-parallel groups, such as SGLang with PP=2, TP=8 and an MTP draft model, ranks outside a worker's TP group enter different collectives, and the load hangs until the distributed timeout or the worker restarts ([#165](https://github.com/dsx-ai-factory/model-streamer/issues/165)). No workaround is recorded.
