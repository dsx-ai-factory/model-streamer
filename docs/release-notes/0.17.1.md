# Model Streamer 0.17.1 - Release Notes

Model Streamer 0.17.1 is a patch release for 0.17.0, spanning 9 merged PRs from 4 contributors. Every change was cherry-picked onto `release/0.17`. The wheels are now tagged `manylinux_2_28` and **install on glibc 2.28 and newer**, where the 0.17.0 wheels needed glibc 2.30. Four loads that failed now complete: **interrupted reads are retried**, **direct I/O alignment is probed at a non-zero file offset**, **packed 4-bit float tensors load**, and **a lone reader no longer deadlocks**. Reads into CUDA device destinations through the C API are **direct**, which was 1.98x faster in the PR's measurement: 4.97 to 9.86 GiB/s on a 34.88 GiB FP8 model on an H200 GPU.

## Summary

### Install: Wheels for glibc 2.28

The 0.17.0 wheels required glibc 2.30 because they referenced `sem_clockwait@GLIBC_2.30` and newer libm symbols. The semaphore now resolves `sem_clockwait` at run time and falls back to `sem_timedwait` when it is missing, and the link rules select older compatible libm symbols. All four packages are tagged `manylinux_2_28` for x86_64 and aarch64, so vLLM's `manylinux_2_28` lock-generation targets can use them ([#301](https://github.com/dsx-ai-factory/model-streamer/pull/301), from [#300](https://github.com/dsx-ai-factory/model-streamer/pull/300)).

### Loads: Interrupted Reads, Mount Alignment, Packed F4 & Lone Readers

A signal that interrupted an `io_uring` or `libaio` read reached the streamer as the kernel's restart code, errno 512, and failed the whole load. A DeepSeek-R1 FP8 load at TP=8 died with `Read failed with errno 512`. Such a read is now issued again, within a bounded number of attempts per chunk ([#312](https://github.com/dsx-ai-factory/model-streamer/pull/312), from [#298](https://github.com/dsx-ai-factory/model-streamer/pull/298)). The direct-I/O alignment probe now reads at a non-zero file offset, so a mount that enforces alignment on the offset no longer passes the smallest block size and then refuses real reads with `EINVAL` ([#305](https://github.com/dsx-ai-factory/model-streamer/pull/305), from [#273](https://github.com/dsx-ai-factory/model-streamer/pull/273)). Tensors of dtype `float4_e2m1fn_x2` load, where the reader had rejected valid files as corrupted ([#292](https://github.com/dsx-ai-factory/model-streamer/pull/292), from [#285](https://github.com/dsx-ai-factory/model-streamer/pull/285)). One rank can stream alone while its peers wait elsewhere without deadlocking ([#303](https://github.com/dsx-ai-factory/model-streamer/pull/303), from [#282](https://github.com/dsx-ai-factory/model-streamer/pull/282)).

### GPU Reads: Direct Reads for Device Destinations

A read into device memory lands in a pinned host buffer that the library owns, and it was almost always issued buffered whatever strategy was configured. The read is now rounded outward to whole blocks, so it can be direct. The PR measured 4.97 to 9.86 GiB/s, 1.98x, on Qwen3.6-35B-A3B-FP8 (42 files, 34.88 GiB) on an NVIDIA H200 GPU through the C API with `io_uring_direct` on both runs. The Python API still reads to host memory ([#306](https://github.com/dsx-ai-factory/model-streamer/pull/306), from [#288](https://github.com/dsx-ai-factory/model-streamer/pull/288)).

## Baseline

| Component | Requirement |
|---|---|
| Operating system | Linux with glibc 2.28 or newer (`manylinux_2_28` wheels) |
| Architectures | x86_64 and aarch64 |
| Framework | PyTorch |
| Storage | Local and network file systems, S3 and S3-compatible stores, GCS and Azure Blob |
| Storage packages | `runai-model-streamer[s3]`, `[gcs]` or `[azure]`, installed at the same version as `runai-model-streamer` |
| GPU destinations (C API) | NVIDIA CUDA; `libcuda.so.1` is loaded at run time |

## Upgrade Notes

These matter when moving from 0.17.0. For 0.16.1, read the [0.17.0 notes](https://github.com/dsx-ai-factory/model-streamer/blob/master/docs/release-notes/0.17.0.md) first.

- **Wheel tag.** The wheels are tagged `manylinux_2_28` instead of `manylinux_2_30` ([#301](https://github.com/dsx-ai-factory/model-streamer/pull/301)). Nothing changes for a system that already installed 0.17.0.
- **A load that is not distributed no longer sets the process group size.** `SafetensorsStreamer` loads with `is_distributed=False` skip rank discovery and no longer write `RUNAI_STREAMER_PROCESS_GROUP_SIZE`. When nothing else sets it, each process uses the full file system queue depth and Azure concurrency, instead of 1/N of them with N processes on the node ([#303](https://github.com/dsx-ai-factory/model-streamer/pull/303)).
  > **Migrate:** If several processes on one node stream without `is_distributed`, set `RUNAI_STREAMER_PROCESS_GROUP_SIZE` to their number to divide the depth between them.
- **Empty tensors are yielded on the requested device.** They were yielded on the CPU even when a CUDA device was requested ([#286](https://github.com/dsx-ai-factory/model-streamer/pull/286), from [#280](https://github.com/dsx-ai-factory/model-streamer/pull/280)).

## Features & Improvements

- **Direct Device Reads:** Rounded a staged read outward to whole blocks so a read into a pinned staging buffer can be direct, aligned the staging pool's buffers, and rounded slab sizes up to whole buffers so pinning is not repeated more often ([#306](https://github.com/dsx-ai-factory/model-streamer/pull/306)).
- **Rank Discovery Control:** Added the `discover_ranks` keyword to `DistributedStreamer.stream_files()`, `True` by default. `SafetensorsStreamer` passes `discover_ranks=is_distributed`, so a load that is not distributed never enters the collective. A distributed load still discovers ranks ([#303](https://github.com/dsx-ai-factory/model-streamer/pull/303)).
- **Open Failures Logged:** A file that cannot be opened now logs the reason, so a descriptor limit (`EMFILE`) no longer looks like a missing file (`ENOENT`) or a permission error (`EACCES`) ([#313](https://github.com/dsx-ai-factory/model-streamer/pull/313), from [#308](https://github.com/dsx-ai-factory/model-streamer/pull/308)).

## Bug Fixes

- **Interrupted Reads:** Fixed a signal ending a load with errno 512. The retry budget is per chunk and is not reset when a chunk makes progress, so a read that keeps being interrupted still fails with the errno it received ([#312](https://github.com/dsx-ai-factory/model-streamer/pull/312)).
- **Mount Alignment:** Fixed direct reads failing with `EINVAL` on mounts that check alignment on the file offset. When a file is too short to probe a block size, the probe assumes the larger of the smallest untried size and the page size ([#305](https://github.com/dsx-ai-factory/model-streamer/pull/305)).
- **Packed F4 Tensors:** Fixed the reader validating one byte per logical value for `float4_e2m1fn_x2`. It now halves the last axis for packed dtypes. A shape torch cannot represent, such as a scalar or an odd last axis, raises `cannot be represented` ([#292](https://github.com/dsx-ai-factory/model-streamer/pull/292)).
- **Lone Readers:** Fixed a deadlock when one rank streamed alone while its peers waited in another collective, as when one rank reads CPU tables after all ranks loaded GPU shards ([#303](https://github.com/dsx-ai-factory/model-streamer/pull/303)).
- **Empty Tensors:** Fixed zero-element tensors being allocated without a device ([#286](https://github.com/dsx-ai-factory/model-streamer/pull/286), from [#280](https://github.com/dsx-ai-factory/model-streamer/pull/280)).
- **Thread Pool Shutdown:** Fixed a request popped after the pool stopped still being handled, which could start reads that were then aborted, or download into a buffer the caller had already freed ([#309](https://github.com/dsx-ai-factory/model-streamer/pull/309), from [#302](https://github.com/dsx-ai-factory/model-streamer/pull/302)).

## Testing & CI

- C++ regression tests cover the production semaphore and math linker redirects ([#301](https://github.com/dsx-ai-factory/model-streamer/pull/301)).
- `Handle.Stopped` no longer fails intermittently under load ([#309](https://github.com/dsx-ai-factory/model-streamer/pull/309)). The client manager test no longer assigns through a shadowed pointer, and the logging test no longer needs glibc 2.30 ([#292](https://github.com/dsx-ai-factory/model-streamer/pull/292)).

## Known Issues

### Distributed Streaming

#### Hang When Ranks Belong to Separate Model-Parallel Groups

Distributed streaming takes its participants from the default process group. In a deployment with separate model-parallel groups, such as SGLang with PP=2, TP=8 and an MTP draft model, ranks outside a worker's TP group enter different collectives, and the load hangs until the distributed timeout or the worker restarts ([#165](https://github.com/dsx-ai-factory/model-streamer/issues/165)). No workaround is recorded.
